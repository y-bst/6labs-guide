Tell the agents about your game

Agents already understand gameplay. Context in the sidebar gives them what only your studio knows:

  • Documents: files you upload, like design docs and live-ops plans
  • Connectors: live links to tools your company already uses, like BigQuery or Slack

Oracle and Radiologist both use this context when they answer.

Drop in your files

Open Documents and drop files onto the page, or click to browse.

Anything that gives deeper context works: design docs, live-ops plans, player research, balance logs, strategy docs.

PDF · DOC · CSV · TXT · imagesUp to 30 MB each

Files upload side by side

Each file shows its progress while it uploads.

Keep adding more from the bar at the top, or delete any file with the bin.

Tell agents what each file is for

Once a file is up, 6labs asks: What should agents know about this file?

A line or two on its purpose and key topics is what makes the file useful to agents. Save it, or Skip for now.

Ready for every agent

Saved files show their description under the name. Edit it any time with the pencil.

From now on, agents read these files when they answer.

Connectors link your other tools

Connectors are between 6labs and the tools your studio already uses.

  • Active in your company: tools someone at your company has already connected, here BigQuery and Snowflake
  • Available to add: tools ready to connect

Everyone sees it, the owner decides who edits

  • Everyone at your company can see an active connection and who connected it
  • The owner can let teammates edit its descriptions with one switch
  • With the switch on, teammates see Shared · you can edit. With it off, they can view but not edit.

One tool can have several connections, like two BigQuery projects. Each one is a tab.

Each connection shows its health

  • Syncing: 6labs is still importing the tables
  • Needs work: already usable, but some descriptions are missing
  • Ready: connected and ready to query
  • Error: access was removed. Oracle stops using it until someone reconnects.

Describe the data. It stays yours.

Like documents, each table and column can carry a short description, so Oracle knows what the data means. The more are filled in, the sharper the answers.

6labs only reads from your tools and never writes back. Descriptions live in 6labs, not in your warehouse.

Add context to a single question

In Oracle, the + button adds context to one question: Attach PDF, or pick a connected tool under Connectors.

Say it to a client

  • Upload your design docs once and every agent uses them.
  • Connect BigQuery or Snowflake and ask Oracle about your own numbers.
  • Read-only: 6labs never changes your data.

Questions clients ask

What files can we upload?

PDF, DOC, CSV, TXT and images, up to 30 MB each.

Do we have to describe every file?

No, you can skip it. But a short description is what helps agents use a file well.

Which tools can we connect?

The Connectors page lists BigQuery, Snowflake, AppsFlyer, Jira, Slack, Discord and Facebook Ads.

Can 6labs change our data?

No. It only reads from your warehouse. Descriptions are stored in 6labs, not in your tools.

Who can see a connection?

Everyone at your company. Each connection has an owner, who decides whether teammates can edit its descriptions.

What if a connection breaks?

It shows Error with the reason, like a removed permission. Fix access in the tool and click Reconnect.
